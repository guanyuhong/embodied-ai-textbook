# 内容标准

本规范用于控制章节内容边界、理论深度和平台内容比例。

## 1. 章节内容边界

- 导论章聚焦基本定义、核心问题、学习路径和系统观。
- 理论章先讲通用原理，再讲方法与算法，最后讲平台与工具。
- 实验或项目章节可以展开平台实践，但仍需以通用任务目标和评价指标为主线。
- 第 12 章集中处理仿真平台对照，第 14 章集中处理高校实验平台组织。

## 2. 平台内容后移原则

第 1 章只保留平台层级说明，不展开以下内容：

- 任务包字段、schema 或配置格式。
- Runner 命令、训练/推理接口。
- 回放文件格式、评测 JSON 样例。
- 平台部署、账号、授权和 SDK 使用。

这些内容应放入第 8、12、14 章或实验手册。资料缺失时统一写“需平台方补充”。

## 3. 最小形式化框架

导论章和任务建模章节应建立以下最小框架，不需要复杂推导：

| 符号 | 含义 |
|---|---|
| `o_t` | 时刻 `t` 的观测，来自传感器或环境输入 |
| `s_t` | 时刻 `t` 的内部状态表示 |
| `g` | 任务目标 |
| `a_t` | 时刻 `t` 的动作 |
| `f_{t+1}` | 行动后的反馈、评价或错误信息 |
| `π` | 从观测、状态和目标到动作的策略 |

推荐表述：

```text
在时刻 t，具身智能体依据观测 o_t、内部状态 s_t 和目标 g 选择动作 a_t；动作改变环境后，系统获得新的观测和反馈，并进入下一轮决策。
```

## 4. 正例、反例和边界例

引入新概念时，优先使用：

- 正例：校园导览机器人、仓储导航机器人、桌面操作机器人。
- 反例：只按固定轨迹运行的自动化设备、只生成文本计划的聊天机器人。
- 边界例：手机导航、虚拟游戏智能体、仿真环境中的具身智能体。

## 5. RaysTwins 内容标准

- RaysTwins 只能作为教学辅助仿真平台之一。
- 第 1 章 RaysTwins 内容控制在 500-800 字以内。
- 不写“本教材完全基于 RaysTwins”“RaysTwins 是唯一选择”等表述。
- 不编造 SDK、API、任务包 schema、Runner 命令或训练接口。
- 详细平台能力、部署、任务包和接口说明后移到相关章节或实验手册。

## 6. 拓展阅读分类

拓展阅读应分组呈现：

1. 基础教材。
2. 机器人与强化学习。
3. 具身智能平台。
4. 本书后续章节对应阅读。

引用来源必须来自 `references/sources.yaml`；新增来源先登记，合并前由 Human Editor 核验。
